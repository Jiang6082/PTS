# PTS — Part-Time Internship Scanner

On-demand scan for **part-time / term-time internships** in **software engineering, data (data science, analytics, ML, data engineering) and finance (asset management, hedge funds, investment research, PE/VC, fintech)** that run between now and **June 2027**: fall 2026, winter and spring 2027, academic-year and remote part-time roles, plus VC scout programs and UChicago research-assistant / student roles. Covers a **308-employer universe** (big tech, AI/data companies, startups, fintech, asset managers, hedge funds, PE/VC, banks, Chicago-area and remote-first employers). Sister project of [QJS](https://github.com/Jiang6082/QJS) and [ECS](https://github.com/Jiang6082/ECS).

**Filter settings:** remote (US) only, except UChicago on-campus roles · any part-time hours, but no full-time off-cycle co-ops · summer-only internships excluded · senior / PhD / MBA-only excluded · investment banking and corporate finance excluded.

## How It Works

1. **v1 — ATS boards** (`scripts/scan_pts_boards.mjs`): every seeded board in [inputs/ats_seeds.json](inputs/ats_seeds.json) (Greenhouse, Lever, Ashby, Workday, SmartRecruiters, Workable, iCIMS, Oracle, Eightfold, Amazon, …) plus guessed Greenhouse/Lever/Ashby slugs. Workday sites are searched for `intern`, `part time` and `student` instead of being fully enumerated.
2. **Detail enrichment** (`tools/enrich.mjs`): postings with student / intern / part-time titles get one detail fetch (Workday job API, SmartRecruiters/Workable/Oracle detail APIs, or the posting's schema.org JSON-LD), because the part-time signal usually lives in the description or a schedule field.
3. **Filter** (`tools/relevance.mjs`): student role → software / data / finance track → date window (now to June 2027; summer-only, past terms and roles running past June 2027 dropped) → remote in the US → part-time signal (commitment field, title, ≤30 hrs/week, academic-year or while-enrolled wording). Term-time roles that say nothing about hours are kept in a separate _hours not stated_ list.
4. **v2 — career pages and web leads** (`scripts/expand_pts_search.mjs`): career pages (auto-discovered via Bing) are scanned for embedded ATS boards; employers with no enumerable source get a web-lead search.
5. **Reports**: two-scan stability guard for new/closed roles, closed-role archive, roster audit (incl. seeded boards that failed), dashboard, this README.

## How to Run

Requires **Node.js 18+** (no dependencies).

```bash
npm run scan:all          # full workflow (v1 + v2 + reports + README)
npm run scan:all:publish  # scan, rebuild reports, commit, push
npm run report:new -- --days=3   # roles released in the last 3 days (by ATS publish date)
npm test                  # offline self-test (stubbed fetch)
```

### On-demand scans (GitHub Actions)

[.github/workflows/scan.yml](.github/workflows/scan.yml) runs `npm run scan:all:publish` only on demand: on manual dispatch, or **on any push that changes [.github/scan-request](.github/scan-request)** — edit the timestamp in that file to start a scan without the Actions tab. There is no daily schedule. `.scan-state/` is cached between runs so new/closed detection keeps working.

### Changing the filter

Window end, hour cap and patterns live at the top of [tools/relevance.mjs](tools/relevance.mjs) (`WINDOW_END`, `MAX_PART_TIME_HOURS`). To allow in-person roles for an employer, set `"localOk": true` on its roster entry (only UChicago and NORC have it now). After editing, run `npm test`.
